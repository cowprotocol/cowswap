# rwa-frontend AGENTS.md

Root rules: [`../../AGENTS.md`](../../AGENTS.md) (global safety, workflow, and verification baseline).
This file: rwa-frontend app-specific commands only.

## App commands

- Start dev server: `pnpm start:rwa`
- Build: `pnpm build:rwa`
- Lint: `pnpx nx run rwa-frontend:lint` (runs `lint-fsd` first)
- FSD check: `pnpx nx run rwa-frontend:lint-fsd` ([steiger](https://github.com/feature-sliced/steiger))
- Test: `pnpx nx run rwa-frontend:test`
- Browser tests (Playwright, `apps/cowswap-e2e-tests/src/rwa`): `pnpm e2e:rwa`. Use them for what Jest's DOM can't evaluate, like `:has()` selectors and real scrolling.
- Typecheck: `pnpm exec tsc -p apps/rwa-frontend/tsconfig.app.json --noEmit`
- Rebuild `data/RWAs.json` from the CoinGecko RWA API: `pnpm --filter @cowprotocol/rwa-frontend update-registry` (run manually, needs `COINGECKO_API_KEY`)
- Fill asset profiles in `data/RWAs.json`: `pnpm --filter @cowprotocol/rwa-frontend update-profiles` (run manually after `update-registry`, needs `ANTHROPIC_API_KEY`). Flags: `--source wikipedia|ai`, `--force` (regenerate filled profiles), `--ticker NVDA` (repeatable), `--dry-run`
- Fill `profile.website` in `data/RWAs.json` from Wikidata (the official website Wikipedia shows): `pnpm --filter @cowprotocol/rwa-frontend update-websites` (run manually after `update-profiles`). Flags: `--force` (replace existing websites), `--ticker NVDA` (repeatable), `--dry-run`. Review every changed website before committing
- Validate `data/RWAs.json` with the app's `validateRegistry` rules: `pnpm --filter @cowprotocol/rwa-frontend validate-registry` (run after hand edits). `update-registry` doesn't write a result that fails it, and `update-profiles` requires a valid registry and rejects profiles that fail it
- Test the registry scripts: `pnpm --filter @cowprotocol/rwa-frontend test-scripts` (`tsx --test`: the app's Jest doesn't run `.mjs`). The scripts run through `tsx` so that `scripts/registryValidation.mjs` can import `validateRegistry.ts`

## Environment

- `COINGECKO_API_KEY`: CoinGecko key (server-only). Without it the keyless public API is used, which is heavily rate limited.
- `COINGECKO_API_PLAN`: `pro` for `pro-api.coingecko.com`; any other value uses the Demo API.
- `ANTHROPIC_API_KEY`: Claude API key, used by `update-profiles` only (never by the app).
- `COW_API_KEY`: CoW Partner API key (server-only), used by `/api/v1/quotes`. Without it the public order book API is used.
- `ONDO_API_KEY`: Ondo GM API key (server-only), for Ondo shares multipliers and stock market data. Without it Ondo equivalent shares are estimated from the token price, and asset pages show the tokenized market only.
- `NEXT_PUBLIC_WC_PROJECT_ID`: Reown project id (defaults to the cowswap-frontend one).
- `NEXT_PUBLIC_ENABLE_SW=true`: register the service worker in dev (production always registers it).
- `NEXT_PUBLIC_BALANCES_WATCHER_BASE_URL`: balances watcher API (defaults to `https://balances-watcher.cow.fi`).
- `NEXT_PUBLIC_SITE_ORIGIN`: origin that serves the app under `/rwa`, used for canonical links, Open Graph and the sitemap (defaults to `https://swap.cow.fi`). Only `VERCEL_ENV=production` is indexable: other deployments get `noindex`.
- `NEXT_PUBLIC_RWA_TOKEN_LIST_URL`: hosted copy of `/api/v1/token-list` for the balances watcher, which only accepts lists from `files.cow.fi` and `raw.githubusercontent.com`. Without it the list's tokens are sent as `customTokens`.

## App rules

- `data/RWAs.json` is the asset registry, rebuilt with `update-registry`. It holds stocks, ETFs and commodities (`RwaAsset.type`), with tokens of every issuer CoinGecko lists on CoW-supported chains: the script skips the assets left without tokens. Issuers are set up as in [Adding or updating an issuer](#adding-or-updating-an-issuer). Every asset has a unique `coingeckoId` (the CoinGecko RWA id). Repeated values are stored once in the top-level `allowedTradingTimes` and `sectors` maps, and assets reference them by number key in `allowedTradingTime` and `profile.sector`: `registry.ts` resolves the keys (`decodeRegistry`), and both scripts read and write the file through `scripts/registryFile.mjs`, which keeps existing keys and drops unused ones. Hand edits must use a key from the map, or add one. Run `validate-registry` after editing it; `validateRegistry.test.ts` checks it too.
- The app trades only on the networks in `RWA_CHAIN_IDS` (`entities/asset/model/networks.ts`), the ones the wallet modal offers. `data/RWAs.json` keeps tokens on every CoW-supported network, and `getRegistry()` leaves out the tokens on other networks and the assets left without tokens. Robinhood Chain is left out until CoW Swap enables it (`isRobinhoodEnabled`): add it to the list then.
- Don't geoblock tokens in this app. The CoW Swap widget enforces geoblocking from its restricted token lists (`libs/core/src/cms`), so a new issuer needs its list there.
- `RwaAsset.newsFeed` is hand-edited and kept by `update-registry`. Use only an RSS or Atom feed on the issuer's own domain (newsroom or IR), never an aggregator. Before adding one, check that it returns XML to a non-browser User-Agent: many IR sites (Q4-hosted ones, for example) are behind Cloudflare or Akamai bot protection. When the feed fails, the asset page hides the news.
- `RwaAsset.profile` fills the About header of the asset page, which shows only the day range and the 52-week range of the 1Y chart when it's missing. `update-registry` keeps it. `description` and `sector` are written by `update-profiles`: the Wikipedia summary of the asset's Wikidata entity (NYSE, Nasdaq, NYSE Arca, NYSE American, HKEX or LSE listing; a ticker listed by several entities is left unmatched) reworded by Claude, or Claude alone from the title and ticker, which skips assets it doesn't know. The description is one or two factual sentences about the company or fund, without figures. `sector` is a `RWA_SECTORS` sector (GICS, plus `ETF` for funds), ` · ` and an industry, e.g. `Information Technology · Semiconductors`; `validateRegistry` enforces it, and `scripts/profiles/sectors.mjs` keeps a copy of the list, so change both. `website` is optional, written by `update-websites` or by hand: `update-profiles` never writes it and keeps it with `--force`. `update-websites` takes the Wikidata official website (`P856`) of the same entity, writes only `https` links reduced to host and path (`sanitizeWebsite` in `scripts/profiles/websites.mjs`), and skips assets without a profile and entities with several websites.
- The asset logo (`RwaAsset.logoUrl`) is static registry data written by `update-registry`; token logos come from `/coins/markets` on the asset page.
- Price, 24h change, day range, market cap and volume of an asset come from CoinGecko `/rwas/markets` (the tokenized market over every chain and issuer), keyed by `coingeckoId`. Per-token data (`/coins/markets`) is loaded for the asset page and for tickers-filtered `/api/v1/assets` (the portfolio, to value each token at its own price); onchain stats only for the asset page. The table and top-movers 1D sparklines are the last 24 points of the `/rwas/markets` 7d sparkline, so they cost no extra request. Its last point lags `updatedAt` by up to an hour, so a 25th point would start the 24h change up to 26 hours back. That sparkline has no timestamps and CoinGecko drops the hours a token didn't trade, so only a full one (169 hourly points) is used (`buildDailySeries`, `buildMarketCapSeries`); a thin asset gets no table sparkline and is left out of the market cap chart, and a thin top mover takes its sparkline from its 1D chart (`getAssetChart`). The asset page price chart is CoinGecko `/rwas/{id}/market_chart` (Pro plan only), per share over every issuer like `market.price`; its candles are built from those points (`toCandlesFromPoints`), as CoinGecko has no RWA OHLC endpoint. Without the Pro plan, or when that chart is empty or fails (then the response is degraded, so it isn't cached), the chart and candles take the first coin of the asset, in registry order, that has prices in the range (an issuer's coin can stop getting prices while another one still trades), one request per coin tried, divided by that coin's shares per token (`getAssetChart`, `getAssetCandles`). Every page shows the same 24h change, from the 1D sparkline (`getDailyChange`), falling back to `/rwas/markets` without a full one, because a bad tick of one token in `/rwas/markets` skews its `price_change_percentage_24h`. The asset page takes only the day range from the 1D chart (`useAssetMarket`), from 24h before `market.updatedAt` because the chart is cached longer than the price. For the same reason, the price chart ends at the shown price (`withLatestPrice`), on both the Stock and Tokenized stock views.
- Styling uses CSS Modules (`*.module.css`) instead of `styled-components/macro`: Turbopack does not run Babel macros.
- Import `@cowprotocol/common-*` libs through side-effect-free subpaths (e.g. `@cowprotocol/common-utils/errors`). Their root entries pull Lingui macros.
- Market data must come through `entities/asset/api/assetsService.ts`. Do not call providers from routes directly.
- The asset page has a **[Stock / Tokenized stock]** toggle (`marketKindAtom`, Stock by default) for `AssetStats`, the price chart and the About ranges. Stock data (`/api/v1/stock/{ticker}`, `/chart` and `/candles` with `market=stock`) comes from `StockDataProvider` providers tried in order (`withStockDataFallback` in `entities/asset/api/stockData.ts`): Ondo now, FinancialData.net planned. Add a provider to that list, not to routes or UI. Ondo is looked up by the asset's Ondo token, so an asset without one has no stock data: the page shows the tokenized market and disables Stock (`shownMarketKindAtomFamily`). Its 24h change and day range come from the `15min/1day` candles, which include extended sessions. Positions, quotes and the token table stay on token prices. See `docs/stock-market-data.md`.
- Shares per token (`RwaMarketData.sharesPerToken`) come from `entities/asset/api/sharesMultipliers.ts`: Ondo's `sharesMultiplier` (it includes stock splits, so it can be below 1), 1 for rebasing xStocks (EVM `balanceOf()` is already scaled), the troy ounces a commodity token holds for the tokens listed in `entities/asset/model/commodityUnits.ts` (no dividends; keyed by CoinGecko id, since an issuer can have both ounce and gram tokens, like Kinesis `KAG` and `KAU`; a commodity token missing there is priced per token), onchain `convertToAssets` for ERC-4626 tokens (`isVaultToken`: wrapped xStocks and ST0x; never the xStocks multiplier for wrapped xStocks: v1 wrappers are anchored at their first deposit), onchain ERC-8056 `uiMultiplier()` for Robinhood tokens (`hasUiMultiplier`: their `balanceOf()` is unscaled), and 1 for cash-payout Dinari and Anchored tokens. Stove Finance and Securitize have no dividend model, so their tokens have no multiplier. Equivalent shares are balance × multiplier. A position is valued at stock price × multiplier when the multiplier is known, and at the token price only without one (`getTokenUsdPrice`): a CoinGecko token id is shared by every network, while wrapped xStocks rates differ per network. Quote/token prices are shown and ranked per share. The dividend model is per token (`getDividendModel(token)`), not per issuer.
- `/api/v1/token-list` is the token list of `data/RWAs.json`. Balances come from the balances watcher for the tokens in that list: the asset page streams them (`useAccountBalances`), the portfolio loads one snapshot per chain, cached for a minute, with a manual refresh (`useAccountBalanceSnapshots`).
- Every balances watcher SSE stream holds one of the browser's 6 HTTP/1.1 connections to its host. Every watcher request goes through the pool in `widgets/account/model/watcherConnections.ts`: snapshot loads with `withWatcherConnection`, live streams with `holdWatcherConnection`. An asset on more than 6 networks streams 5 and loads the rest once (`splitWatchedChains`).
- The trade widget loads the local CoW Swap (`http://localhost:3000`, `pnpm start:cowswap`) in development, the `swap-dev` preview of the same branch on Vercel previews (`relatedProjects` in `vercel.ts`, like the widget configurator), and `swap.cow.fi` otherwise (`WIDGET_BASE_URL` in `shared/config`), so widget changes can be tested before they are deployed. A preview without a `swap-dev` deployment of its branch uses `swap.cow.fi`.
- Account activity must come through `ActivityProvider` (`widgets/account/api/activity`). It is backed by the CoW order book trades for now; swap the implementation there, not in the UI.
- Data fetching uses Jotai: `atomWithQuery` from `jotai-tanstack-query`, with `atomFamily` from `jotai-family` for per-ticker queries. SWR is banned by ESLint. Query options live in `entities/asset/api/assetsQueries.ts`, and every query key starts with `RWA_QUERY_KEY_ROOT`.
- There is one `QueryClient` per app instance (`_app/layout/Providers.tsx`), shared by Jotai (`queryClientAtom`) and wagmi.
- `_app/offline/persistQueryCache.ts` persists app queries to IndexedDB and restores each query when it enters the cache. Don't add a second client-side cache for API data.
- When an API response changes shape, bump `STORE_NAME` in `persistQueryCache.ts` and add the old name to `PREVIOUS_STORE_NAMES`. Otherwise data saved in the old shape is restored as the new type.
- When `RwaAggregateMarket` changes shape, bump `RWA_MARKETS_CACHE_KEY` in `entities/asset/api/marketData.ts`: the Next data cache outlives deployments.
- Every CoinGecko response is cached per URL with `unstable_cache` (`shared/api/coingecko/coingeckoClient.ts`), never with `fetch` `next.revalidate`. Next serves an expired entry once before refreshing it, however old it is, so `createCachedJsonFetcher` (`shared/api/cachedJson.ts`, also used by the Ondo client) refetches an entry older than two `revalidate` periods and serves the old one only when that fails. Next keeps serving a stale entry when its refresh fails, and `withRetryBackoff` spaces the upstream retries of a failing URL: 60s, 120s, 240s and so on, up to an hour, per server instance. Concurrent requests for a URL share one upstream call, which times out after 10s. Only OHLCV treats a 404 as data (`allowNotFound`); elsewhere it's a failure, so it never replaces a good entry. When a cached CoinGecko payload changes shape, bump `RESPONSE_CACHE_KEY` there.
- `/coins/markets` and onchain `tokens/multi` are requested in batches cut from every registry coin id (250) or token address on a network (30), so assets of the same batch share one cache entry. Pass the registry list as `batchIds`/`batchAddresses`, not the ids of a single asset.
- A response built without upstream data sets `degraded: true` (`DegradableResponse` in `@/shared/api`). `jsonResponse` sends it with `no-store`, and the IndexedDB query persistence never saves it, so an outage can't overwrite the last good data.
- The app is served at `https://swap.cow.fi/rwa` (`basePath`, `BASE_PATH` in `shared/config`), on the CoW Swap origin, to share localStorage and the wallet connection. Next.js prefixes `Link`, router and asset URLs, but not `fetch`, `next/image` `src` or metadata URLs: wrap those with `withBasePath`. Local dev runs at `http://localhost:3000/rwa`.
- The wagmi storage key is `WALLET_STORAGE_KEY` from `@cowprotocol/common-const/wallet`, the one CoW Swap uses, so a wallet connected in one app is reconnected in the other. Don't give the wagmi adapter its own storage.
- The theme is shared with CoW Swap: it lives in `userDarkMode` of the persisted CoW Swap user state (`USER_STATE_STORAGE_KEY` from `@cowprotocol/common-const/theme`; `null` is the system theme). `shared/lib/theme` writes only that field. Each app reads it on page load, not while the page is open.
- The header follows the CoW Swap app's mobile chrome at its `MEDIA_WIDTHS` (`libs/ui/src/consts.ts`): hamburger menu at 1280px, wallet in a bar fixed to the bottom at 960px (the footer clears it), search button opening a full-screen search at 720px. Unlike CoW Swap, the "CoW RWA" wordmark stays down to 500px, where the logo becomes icon-only. Use those widths for new media queries; JS reads them from `MEDIA_QUERIES` in `shared/config`. A page puts its own controls in that bar with `WalletBarSlot`: at 960px and below the asset page shows its trade widget right under the chart, with Buy and Sell in the bar while the widget is out of view. Where the wallet leaves too little room, Sell drops first, then Buy: the widget below the chart still offers both. At 720px and below the home filters open in a bottom drawer (`AssetsFiltersDrawer`) built directly on Base UI's drawer, with the motion of `BottomDrawer` in `libs/ui`, which this app can't import because Turbopack doesn't run its `styled-components/macro`. It loads on demand, so wider screens don't download Base UI's drawer. The hamburger menu, full-screen search and drawer lock the page with `body:has()` rules in their CSS modules. Firefox 111–120, within this app's browserslist, has no `:has()`, so the page can scroll behind them there.
- `robots.txt` belongs to the CoW Swap origin, so this app has none: `swap.cow.fi/robots.txt` must list `https://swap.cow.fi/rwa/sitemap.xml`.
- The favicon is the CoW Swap one: `public/favicon-{light,dark}-mode.png` are copies of `apps/cowswap-frontend/public`, linked per color scheme. Update both apps together.
- Icons (`/icons/[size]`) and Open Graph images (`/og-image`, `/asset/[ticker]/og-image`) are static route handlers, not the `icon`/`apple-icon`/`opengraph-image` file conventions: Next.js leaves the `basePath` out of their links, and resolves social images against the branch URL on Vercel previews. `buildPageMetadata` links them with absolute URLs (`DEPLOYMENT_URL`).
- Asset pages are prerendered for upper-case tickers only (`dynamicParams = false`). `proxy.ts` redirects other casings.
- Analytics goes through `trackEvent` from `@/shared/lib/analytics` (the CoW Swap GTM container, `GTM_ID` from `@cowprotocol/common-const/analytics`). Add a new event to `RwaAnalyticsEvents` and to `docs/analytics.md`.
- The service worker (`public/sw.js`) is registered as `/rwa/sw.js?v=<NEXT_PUBLIC_APP_VERSION>` with the `/rwa` scope (allowed by the `Service-Worker-Allowed` header in `next.config.ts`), so each deploy gets fresh caches. It never caches `/api/`, because IndexedDB holds that data.

## Adding or updating an issuer

The registry takes tokens of any issuer CoinGecko lists, so a new issuer shows up after `update-registry` with its CoinGecko name and no dividend model or legal link. Every issuer-specific rule is keyed by the registry name (`RwaToken.issuer`). To set one up:

1. **Name.** If the CoinGecko issuer name is a legal entity or otherwise long (`Robinhood Assets (Jersey) Limited`), map its CoinGecko issuer id (`issuer_details.id` of `/rwas/{id}?tokens=true`, e.g. `robinhood-chain-stocks-ecosystem`) to a short name in `ISSUER_NAMES` of `scripts/updateRegistry.mjs`. `update-registry` keeps the issuer of tokens already in `data/RWAs.json`, so rename those in the file too, then run `validate-registry`. A rename changes the `issuer` of analytics events (`trade_token_select`).
2. **Issuer list and legal link.** Add the name to `RWA_ISSUERS` and its legal documentation or terms page to `RWA_ISSUER_LEGAL_DOCS_URLS` (`entities/asset/model/issuers.ts`); the map is a full `Record`, so the typecheck requires a link for every listed issuer. Check the link answers 200. The asset page and the issuers menu link the issuer name to it (`getIssuerLegalDocsUrl`).
3. **Dividend model.** Read the issuer's own docs (not aggregators) and add the model to `ISSUER_DIVIDEND_MODELS`: `price-accrual` (fixed balance, the token price grows over the share), `rebase` (the balance grows, one token stays one share) or `cash-payout` (paid out separately, one token stays one share). Leave an issuer out when its docs don't say (Stove Finance, Securitize): a wrong model is worse than none, since it drives the dividend note, the premium hint and equivalent shares. A token whose model differs from its issuer's goes through a per-token rule, as `isWrappedXStock` does. Commodity issuers need no model; add each of their tokens to `commodityUnits.ts` with the troy ounces it holds, checked in the issuer's docs.
4. **Shares per token** (`entities/asset/api/sharesMultipliers.ts`, see the shares rule above). `rebase` and `cash-payout` tokens count as 1, which is right only when EVM `balanceOf()` already applies splits and rebases: check it on a token contract. A `price-accrual` token needs its multiplier source: an ERC-4626 wrapper joins `isVaultToken` (`convertToAssets`), an ERC-8056 token joins `hasUiMultiplier` (`uiMultiplier()`), an issuer API gets a client in `shared/api` loaded like Ondo's. Without one, its shares are estimated as token price ÷ stock price, and its prices are compared per token. Read the source onchain for every registry token of the issuer before relying on it (e.g. a viem `multicall` with the chain RPC of `getChainInfo`), and bump the cache key of a loader whose token set or shape changes.
5. **Trading window.** The US market hours are per asset, not per issuer: `RwaAsset.allowedTradingTime` (`DEFAULT_TRADING_TIME` in `scripts/updateRegistry.mjs`, `13:30`–`20:00 UTC` on weekdays, no holidays), which drives the home market status (`isUsMarketOpen`). An issuer that pauses trading at a known time, like xStocks around a multiplier activation, gets it in `loadTradingPause` (`RwaTradingPause`), shown on the asset page and in the trade widget. Weekend RWA quotes are handled by the CoW Swap widget (`useTokenCustomTradeError` in `apps/cowswap-frontend`), not here.
6. **Geoblocking.** Not in this app: the CoW Swap widget needs the issuer's restricted token list in `libs/core/src/cms` (the `rwa-token-list-onboarding` skill).
7. **Docs and tests.** Add a section with its sources to `docs/issuer-dividends.md` (models, multiplier sources, and issuers left without a model), and cases to `issuers.test.ts` and `sharesMultipliers.test.ts`.

## CoinGecko website vs this app

The app shows the tokenized market; coingecko.com stock pages lead with the underlying stock. Expect these differences, and don't "fix" them by mixing sources:

- The coingecko.com headline price and 24h change are the stock's ("Pre-Market • NASDAQ"), with the tokenized price shown separately. The API has no stock price: `/rwas/markets`, `/rwas/{id}` and `/rwas/{id}/market_chart` return tokenized data only (`tokenized_market_data`, `tokenized_prices`). Thin or off-hours tokens drift from the stock (ENLV on 2026-10-28: $2.78 tokenized vs $2.53 stock).
- coingecko.com top gainers rank by the stock change over every RWA; ours rank by the tokenized change over the registry. An asset with stale tokenized data (Ultra Clean Holdings, frozen since 2026-10-16) has a `null` change and no chart here while coingecko.com still lists it; an asset missing from `/rwas/markets` (Critical Metals) isn't here at all.
- coingecko.com "Tokenized Mcap" sums every `/rwas/markets` asset (gold alone is most of it); `totals.marketCap` sums the registry only.
- Bad ticks in a token feed reach both (ENLV on 2026-10-27, `/rwas/markets` 24h change about +1,590%). They roll off with the 24h window.
- The Stock view uses Ondo's `underlyingMarket` (Ondo assets only), which doesn't always match coingecko.com. `market.price` and the Tokenized stock view are the tokenized price per share.

## Architecture: Feature-Sliced Design

Follows [FSD for Next.js](https://feature-sliced.design/docs/guides/tech/with-nextjs), enforced by steiger (`steiger.config.ts`).

- `app/` (project root) is Next.js routing only. Every file re-exports from `src/_app` or `src/_pages`, including API routes (`export { getAssetsHandler as GET } from '@/_app/api-routes'`).
- `src/` layers, top to bottom: `_app` → `_pages` → `widgets` → `features` → `entities` → `shared`. A layer imports only from layers below it. Slices on the same layer do not import each other.
- `_app` and `_pages` carry the `_` prefix so they don't clash with Next.js `app`/`pages`.
- Import other slices only through their public API (`index.ts`), e.g. `@/entities/asset`. Inside a slice, use relative imports.
- Server-only code has a separate public API, `index.server.ts` (e.g. `@/entities/asset/index.server`, `@/shared/api/index.server`), and starts with `import 'server-only'`, so a client import fails the build.
- Segments are named by purpose (`ui`, `model`, `api`, `lib`, `config`), not by kind (`components`, `hooks`, `providers`).
- Pages first: keep code in the page slice until a second consumer needs it, then extract a feature or widget. steiger's `insignificant-slice` rule flags slices with a single consumer.
